## 开始前准备

先完成 [Windows Codex 配置](/docs/windows-install-codex) 或 [Mac / Linux Codex 配置](/docs/mac-install-codex)，确认 Codex 能正常对话。实际生成图片时，还需要本站接口可用的 API Key 和对应模型权限。

本教程将 `imagegen2` 的默认模型设为本站接口使用的 `gpt-image-2.6`，提供静态图片生成、参考图编辑和 GIF 动图生成功能。

## 1. 一键创建、升级或修复 imagegen2

在 Codex 新建对话，复制下面整段提示词并发送。已经安装旧版的用户也可以直接使用。

```text
请使用 $skill-creator 创建、升级或修复用户级 Codex Skill：imagegen2。

目标：默认使用 gpt-image-2.6，支持图片生成、参考图编辑和 GIF 生图；降低安装门槛，使用宽松的输出校验，特别是不要因返回尺寸不一致而丢弃已生成图片。

请直接完成能够执行的安装、环境准备和检查，尽量由你运行命令。仅在遇到无法自行解决的必要信息或权限限制时说明原因。默认不进行真实 API 测试，不产生生图调用；不要把缺少密钥、模型权限或网络暂时不可用判断为 Skill 文件安装失败。

一、安装与现有文件

1. 阅读系统内置 $skill-creator 的说明。若该技能不可用，按下述要求创建普通 Codex Skill，并说明使用了手动创建方式。
2. Skill 名称保持 imagegen2。Codex 根目录使用已设置的 CODEX_HOME，否则使用 Path.home()/.codex。
3. 本教程的安装位置为 <Codex根目录>/skills/imagegen2。已存在时先读取相关说明和脚本，原地更新，保留无关用户修改、未知文件和现有调用策略；不要修改系统内置 imagegen。
4. 确保存在 SKILL.md、agents/openai.yaml、scripts/imagegen2.py。不存在时可使用 skill-creator 的初始化工具，也可直接创建必要文件。
5. 不必添加 README、变更日志等无关文件。临时验证文件放在当前工作目录的临时子目录，不混入正式 Skill。

二、运行环境

1. 优先使用现有 Python 3：检查 python、python3、Windows 的 py，以及已安装的 uv。能实际运行脚本即可，不为了版本号强制升级或重装。
2. 网络请求和基本保存逻辑优先使用 Python 标准库。Pillow 仅作为可选图片解码和 GIF 帧信息检查工具；没有 Pillow 时，基本生成、保存和 dry-run 仍应可用。
3. 没有可用 Python 但已有 uv 时，用 uv run 准备运行时。不固定 Python 或 uv 的具体版本。
4. 两者均不可用时，可按 uv 官方安装说明在当前用户权限内安装，不使用管理员提权或 sudo，不改动无关环境配置。若环境不允许安装，仍完成 Skill 文件，并明确“运行环境尚未就绪”。
5. 若 quick_validate.py 需要 PyYAML，使用可用的隔离环境或 uv run --with pyyaml 执行；不能运行时检查必要文件和 YAML 基本结构，并标注该验证未执行。PyYAML 不作为生图脚本的运行依赖。

三、接口与默认值

生成接口：
- 默认：https://img.ailink1.com/v1/images/generations
- 备用：https://ai.ailink1.com/v1/images/generations

编辑接口：
- 默认：https://img.ailink1.com/v1/images/edits
- 备用：https://ai.ailink1.com/v1/images/edits

默认值：
- model：gpt-image-2.6
- n：1
- size：auto
- quality：medium
- background：auto
- output_format：png
- timeout：600 秒网络空闲超时
- 输出目录：当前工作目录下的 output/imagegen2/

保留 --model 显式选择其他模型的能力，不把模型名称写成仅允许旧版本的封闭列表。不要静默更换用户指定的模型。

不要求安装时必须通过接口连通性探测。优先使用默认接口；可以在正式请求前选择备用接口。正式 POST 发出后，遇到超时、连接中断或 5xx 不得自动切换接口重放请求，也不要为了“通过测试”反复生图。说明结果可能尚未确定，核对后再决定是否重试。

四、认证

API Key 只从 auth.json 的顶层非空字符串 OPENAI_API_KEY 读取。

实现 load_openai_api_key(auth_file=None)：显式 --auth-file 优先，否则读取 <Codex根目录>/auth.json。--auth-file 只接受文件路径。不要扫描整个磁盘。

不要从环境变量、命令参数、聊天内容、标准输入或交互提示获取 Key；不要让用户把 Key 粘贴给 AI。不要在日志、错误、dry-run、源码、输出文件或 openai.yaml 中写出 Key、完整 auth.json 或 Authorization 请求头。

没有可用 auth.json 时仍完成安装和 dry-run，报告实际检查的文件路径；真实调用标记为未执行。不要修改用户的认证文件或覆盖已有配置。

五、命令与参数

以下 scripts/imagegen2.py 指 Skill 目录中的脚本。实际执行时使用已安装脚本的完整路径，并保持用户当前工作目录，不要写死用户名或切换到 Skill 目录保存图片。

支持：
python scripts/imagegen2.py generate --prompt "..."
python scripts/imagegen2.py edit --image "reference.png" --prompt "..."
python scripts/imagegen2.py generate --prompt "..." --output-format gif

参数包括：
- --prompt、--prompt-file
- --image，可重复传入；--mask，可选 PNG mask
- --n：1-10，默认 1
- --ratio：1:1、16:9、4:3、3:4、9:16
- --resolution：1K、2K、4K
- --size：auto 或 WIDTHxHEIGHT
- --model：默认 gpt-image-2.6，允许用户显式传入其他非空模型名
- --background：auto、transparent
- --output-format：png、webp、jpeg、jpg、gif；jpg 归一为 jpeg
- --quality：low、medium、high、auto
- --out-dir、--out、--force、--dry-run、--auth-file、--timeout

生成使用 JSON；编辑使用 multipart/form-data，支持多张参考图和可选 PNG mask。输入图检查存在、可读、非空、基本格式，以及 50 MB 文件大小上限即可，不要求输入图与目标输出尺寸相同。mask 必须是 PNG；不要替用户静默修改原图或 mask。

六、宽松处理尺寸、格式和背景

1. 没有尺寸要求时发送 size=auto。显式 --size 优先；正整数 WIDTHxHEIGHT 只做语法检查，不因为未列入本地尺寸表而拒绝，也不静默改写。
2. 只指定 --ratio 时使用 1K，只指定 --resolution 时使用 1:1。以下是生成请求的参考映射，不是返回图片的验收白名单，也不是全部模型支持尺寸的承诺：
   1:1：1K=1024x1024，2K=2048x2048，4K=2880x2880
   16:9：1K=1536x864，2K=2048x1152，4K=3840x2160
   4:3：1K=1280x960，2K=2048x1536，4K=3264x2448
   3:4：1K=960x1280，2K=1536x2048，4K=2448x3264
   9:16：1K=864x1536，2K=1152x2048，4K=2160x3840
3. 发送后以接口实际返回为准。请求 1536x864、实际返回 1536x1024 时，应保存并提示两组尺寸，不抛出尺寸异常，不因这一差异返回失败状态。
4. size=auto 接受实际返回尺寸。若本地轻量解析器无法读取宽高，但能识别图片格式，仍保存并标注“尺寸未读取”，不要仅因此中断。
5. 请求格式与实际格式不同，按实际格式修正保存后缀并提示。例如请求 PNG、返回 WebP，就保存为 .webp；不得仅更改后缀伪装格式，也不自动重新生图。
6. 不为了满足尺寸校验而自动裁剪、拉伸、放大或覆盖原图。用户另行要求精确像素时，再处理副本，并说明处理方式。
7. 透明背景优先使用 PNG 或 WebP。transparent 与 JPEG/GIF 组合时清楚说明不兼容，不静默去掉透明需求；不要照搬旧版本规则，将 gpt-image-2.6 的透明背景一律提前拒绝。模型能力以当前接口响应为准，失败时不自动换模型。

七、GIF 与输出保存

1. GIF 默认使用 generate、gpt-image-2.6、size=auto、n=1。根据提示词描述动作和循环效果，不强制固定尺寸、帧数、时长或每帧必须不同。
2. 本版只提供 GIF 生成，不承诺 GIF 输入、GIF 编辑或透明 GIF。遇到这类请求说明范围，保留用户原始需求，不静默转换为普通静态图编辑。
3. 如果 Pillow 可用，尽量读取 GIF 帧数、总时长和循环信息；没有 Pillow 或扩展检查无法完成时，保存通过基本格式检查的文件并标注“动画未进一步验证”。不要因为缺少可选依赖就禁止请求。
4. 若能确认 GIF 只有一帧，仍保存并报告“文件已保存，但动画要求未满足”。若请求 GIF 却返回 PNG，也保存真实 PNG 并明确“返回的是静态图片”；不能宣称 GIF 动画生成成功。
5. 响应支持 b64_json、base64_json、base64、image_base64、url、image_url。base64 可处理常见 data URI 前缀和空白；URL 只允许 http 或 https。下载图片不要附带 API Key。
6. 保留必要检查：无效 base64、空响应、错误 JSON/HTML 冒充图片、无法识别为支持的图片格式，或明确损坏的数据，应报告失败。不要把“校验宽松”实现成任意字节都当图片。
7. 成功返回的图片逐张保存。一部分结果缺失或无效，不丢弃其余已取得的有效图片；报告请求数量、保存数量和具体未完成项。
8. 自动创建输出目录，按真实格式保存原始文件。默认不覆盖已有文件；文件名冲突时可增加编号并报告最终路径。使用独占创建避免并发覆盖，只有用户显式 --force 才覆盖。
9. 图片已有效保存但尺寸、格式或动画要求未完全满足时，报告“已保存，附提示”；没有取得有效图片时，才报告该调用失败。保存成功不等于所有创作要求都已满足。

八、检查与报告

1. 默认仅验证必要文件、语法、--help 和 dry-run；某项检查不能执行时继续完成不依赖它的工作。
2. 可用时运行 quick_validate.py。保留合法的现有 frontmatter 字段，不为了格式统一删除用户 metadata。
3. dry-run 显示脱敏的 endpoint、model、n、size、quality、background、output_format、输入与输出路径；脚本本身不读取认证、不发网络请求、不生成输出图片。
4. 至少检查默认生成、16:9+1K 和 GIF 的 dry-run。检查尺寸差异只产生提示、格式差异按实际后缀保存；可用本地小样本验证，不需要真实调用 API。
5. 安全检查关注是否存在实际密钥、硬编码凭证和敏感输出；不要因为源码出现正常的 OPENAI_API_KEY 字段名或设置 Authorization 请求头就误报失败。
6. SKILL.md 写明默认模型、认证来源、输出目录、宽松保存规则、GIF 范围和跨平台用法。agents/openai.yaml 的 display_name 使用 Image Gen 2.6，short_description 简洁清楚，default_prompt 包含 $imagegen2。
7. 只有用户另行要求时，才做真实生成、编辑或 GIF 测试。每类最多提交一次，不将某类能力失败扩大为整个 Skill 安装失败。
8. 最后分别报告：文件安装状态、运行时状态、基础检查结果、真实 API 是否测试。列出 Skill 路径、实际运行方式，以及真实调用时的 auth.json 路径（仅路径）、请求参数、实际格式和尺寸、提示信息、保存文件绝对路径。

请完成上述安装或修复；不要只返回方案，也不要把安装提示词中的示例误当作本次已授权的付费生图测试。
```

## 3. 生成图片

日常使用直接描述内容即可：

```text
$imagegen2 生成一张未来城市夜景，电影感，横版 16:9，保存为 PNG。
```

需要更高清时，可以明确提出：

```text
$imagegen2 生成一张 16:9 的未来城市海报，按 2K 档位请求，使用 high 质量。请保存原始返回图片，并告诉我实际像素尺寸。
```

`1K / 2K / 4K` 用于选择请求尺寸；实际结果以返回文件为准。默认输出目录为当前工作目录下的 `output/imagegen2/`。

```text
$imagegen2 编辑这张图片：将背景改成雨夜，增加霓虹灯反光，保持主体和主要构图不变。保存为新文件，并报告实际尺寸。
```

```text
$imagegen2 以第一张图作为主体和构图参考，以第二张图作为配色与光线参考。保留第一张图的人物身份和服装，输出一张新图片。
```

## 5. 生成 GIF 动图

复制以下示例：

```text
$imagegen2 使用 gpt-image-2.6 生成一个 GIF 动图：一颗橙色小球在白色背景上上下弹跳，动作连贯、自然循环，不要文字。使用 size=auto、quality=low，生成 1 个 GIF。请报告实际尺寸，以及能够读取到的帧数和播放时长。
```

2026 年 11 月 5 日，本教程采用的默认接口和 `gpt-image-2.6` 名称已完成一次 GIF 实测：返回 439 × 390、9 帧、每帧 120 ms 的循环动图。这是该次测试结果，**不是后续 GIF 必须满足的尺寸、帧数或时长**。

## 6. 尺寸不一致时怎么处理

例如请求 `1536 × 864`，接口实际返回 `1536 × 1024`，新版应给出类似结果：

```text

实际尺寸：1536 × 1024
提示：返回尺寸与请求不同，已保留原始图片。
```

此时不应为了“校验通过”重新生图。若确实需要精确尺寸，可以继续发送：

```text
请保留生成的原图，另存一份 1536×864 的版本。优先通过留白适配，不要拉伸主体；告诉我采用了什么处理方式。
```

## 常见问题

### 找不到 imagegen2

先新建对话并输入 `$imagegen2`。仍无法识别时，重新打开 Codex，并让 AI 检查报告中的安装路径与当前客户端的 Skill 加载情况。不要反复安装到多个未知目录。

### 提示找不到密钥

让 AI 报告它检查的 `auth.json` 路径，确认与安装教程使用的 Codex 配置目录一致。文件应包含顶层 `OPENAI_API_KEY` 字符串。

不要把密钥、完整配置文件或带密钥的截图发到聊天或技术支持群。缺少密钥时，可以先完成 Skill 安装，再按原配置教程在本机补全认证。

### 模型、透明背景或指定尺寸被接口拒绝

查看接口返回的具体原因。模型名称、权限和参数是否可用，由当前接口决定；本教程使用的默认模型名是 `gpt-image-2.6`。

对于尺寸参数错误，可在下一次请求中尝试 `size=auto`。透明背景优先选择 PNG 或 WebP。不要将“保存时不严格比对尺寸”理解为接口一定接受任意尺寸。

### 缺少 Pillow 或 PyYAML

本教程要求 Pillow 只用于可选的图片检查，PyYAML 只用于 Skill 结构验证。缺少它们不应阻止基本安装、dry-run 和标准库支持的图片保存；报告应注明哪些额外检查没有执行。

### GIF 没有动起来

先用支持 GIF 动画的查看器打开保存的文件，并查看报告中的实际格式和帧数。如果实际返回的是 PNG 或单帧 GIF，说明这次调用没有满足动画要求，不能靠修改扩展名解决。

### 请求超时或出现 5xx

不要连续重复提交。先查看本地是否已有输出，并核对平台任务记录或用量，再决定是否重新请求或改用备用接口。超时不等于服务端一定没有开始处理。

### 如何向技术支持反馈

提供操作系统、Codex 版本、Skill 路径、模型名、请求参数和已脱敏的错误信息即可。如果图片已保存但尺寸或格式不同，同时提供请求值和实际值，便于判断问题发生在请求、接口还是保存环节。
